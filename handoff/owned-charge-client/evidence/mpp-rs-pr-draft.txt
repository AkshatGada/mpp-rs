Title
feat(client): add an owned charge client without redirects

Body

Endpoints that use an API credential alongside MPP advertise
Payment-Authorization. Fetch and PaymentMiddleware reject these offers because
their caller-owned HTTP clients cannot establish a redirect guarantee.

Add ChargeClient, constructed from ClientBuilder with redirects disabled as the
final setting. Both the initial request and every paid retry execute through
its retained private client, preserving ordinary Authorization when the payment
uses Payment-Authorization. Redirect responses are returned without following
Location, including redirects to the same origin.

Payment requires a valid request-level Accept-Payment preference. Missing,
malformed, repeated and all-zero preferences cannot authorize payment; client
default headers do not authorize it. Filter out session offers before provider
preparation and recheck selected/prepared challenges against transport limits,
provider support, request preferences and expiry. Accept valid header casing
without rewriting the challenge's bound spelling. Retain the existing Fetch,
middleware and session-management guards.
